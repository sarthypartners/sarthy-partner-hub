This is the full version of the grouping logic Partnership SOP v1.0 §11 only summarizes. Used to decide where the Associate's limited calling time goes first, and to sequence the migration wave plan.

The core signal: wallet trend, not a one-time label

Giver vs. Taker isn't a fixed category assigned once - it's read from a partner's actual behavior over time, using the credit wallet as the evidence:

  • Giver pattern: wallet balance trending upward - referring more than receiving, leads converting, low decline rate
  • Balanced pattern: wallet roughly stable - giving and receiving in reasonable proportion
  • Taker pattern: wallet balance trending downward - receiving regularly, referring rarely or never
  • At-risk pattern: approaching the -2,997 freeze threshold, or 4+ consecutive declines flagged

Priority tiers for outreach

How this differs from the evaluation-stage Giver/Taker read

SOP §5 describes an initial, conversation-based Giver/Taker judgment made during onboarding - useful, but subjective and only a snapshot. This framework replaces that snapshot with an ongoing, data-driven signal once a partner has real wallet activity - the onboarding read is a starting guess, this is the actual measurement.
