This is the full version of the grouping logic Partnership SOP v1.0 §11 only summarizes. Used to decide where the Associate's limited calling time goes first, and to sequence the migration wave plan.

Redesigned to fix a real vocabulary problem: this used to be a 5-tier list that reused words like "At-Risk" and "Dormant" already meaning something different in the Data Dictionary's account status field. It's now two separate fields with no overlapping words - status (what the account can do) and giving_pattern (how the partner behaves, only meaningful when status is Active).

Field 1: Account status - unchanged from the Data Dictionary

This is the same status field defined there - Applicant, Active, At-Risk, Dormant, Frozen, Exited. It controls what the account can actually do on the platform. This document doesn't redefine it, just uses it.

Field 2: Giving pattern - new, only applies when status is Active

Not a fixed label - read from wallet trend over time:

  • Giver: wallet balance trending upward - referring more than receiving, leads converting, low decline rate
  • Balanced: wallet roughly stable - giving and receiving in reasonable proportion. This is the default state for most partners most of the time, not an edge case.
  • Taker: wallet balance trending downward - receiving regularly, referring rarely or never

Giving pattern only means something for an Active account. A Dormant or Frozen account doesn't get a giving pattern - its status already says everything that matters for how to handle it.

How this differs from the evaluation-stage Giver/Taker read

SOP §5 describes an initial, conversation-based Giver/Taker/Balanced judgment made during onboarding - useful, but subjective and only a snapshot. The giving_pattern field replaces that snapshot with an ongoing, data-driven signal once a partner has real wallet activity.

Feeds directly into

  • The Dormant-Partner Reactivation process (SOP §17) - accounts with status Dormant are its target list
  • The Migration Wave Plan - Active/Giver and Active/Balanced partners are natural early-wave candidates once rollout expands
  • The Associate's daily call queue, using this exact combined table - see the Interim Operating System
